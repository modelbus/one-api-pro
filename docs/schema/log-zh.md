# 调用日志（Log）

## 这是什么

`Log` 记录**每一次对 `/v1/*` 的调用**：发起人、模型、token 消耗、命中渠道、状态码、错误信息。所有调用痕迹都持久化下来，方便后续排查与审计。

## 在哪里看到

- **后台 → 日志**：筛选时间范围、用户、模型、状态码；分页加载
- **个人中心 → 我的日志**：当前用户自己的日志（精简版）
- **后台 → 运营仪表盘**：当日 / 当月的调用统计

## 关键字段（运维视角）

| 字段 | 含义 | 设置后影响 |
|---|---|---|
| 发起用户 | User | 排查「谁在调」 |
| 发起 Token | Token | 排查「哪个 Key 在调」 |
| 命中渠道 | Channel | 排查「上游走的是哪条路」 |
| 模型 | `gpt-4o` / `claude-sonnet-4` 等 | 排查「用的是什么模型」 |
| 输入 / 输出 token | 数字 | 算费用、定位超额 |
| 状态码 | 200 / 401 / 429 / 5xx | 失败时第一时间看这里 |
| 错误信息 | 文本 | 上游 Provider 返回的原始错误 |
| 耗时 | 毫秒 | 排查慢请求 |
| 扣费额度 | 数字 | 该次调用最终消耗的内部额度 |

## 常见排查路径

- **用户报「扣多了额度」**：日志里查「输入/输出 token」与「命中渠道」，与上游 Provider 对照，看 token 计算是否一致
- **用户报「一直 429」**：日志里看错误信息是不是「额度不足」；再查用户当前 `quota`
- **用户报「调不通某个模型」**：日志里看「命中渠道」是不是空；渠道列表里该模型是否被勾选
- **慢请求定位**：按耗时降序看「命中渠道」；某条渠道持续慢就是它的问题

## 清理与归档

日志会无限增长。建议在生产环境配置定期清理（保留 90 天即可）。后台「日志」页底部「清理历史」按钮可一键删除早于指定时间的日志。

## 相关 API

- `GET /api/log/` — 列表（管理员）
- `GET /api/log/self` — 当前用户的日志
- `GET /api/log/stat` — 统计
- `DELETE /api/log/` — 清理历史日志
