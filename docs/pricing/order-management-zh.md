# 订单中心（管理员视图）

> 后台 → 订单管理。管理员视角的全站订单。

## 在哪里

后台 → 订单管理。

## 列表看到什么

每行展示：

- 订单号
- 类型 chip（套餐 / 充值）
- 用户摘要
- 金额 / 套餐名
- 支付方式
- 状态 chip（待支付 / 已支付 / 已取消 / 已退款）
- 来源（用户自助 / 管理员）
- 下单时间

顶部下拉：按订单类型 / 状态 / 来源筛选。顶部搜索框：按订单号 / 支付流水号模糊搜。

## 怎么筛选

| 下拉 | 选项 |
|---|---|
| 订单类型 | 全部 / 套餐 / 充值 |
| 状态 | 全部 / 待支付 / 已支付 / 已取消 / 已退款 |
| 来源 | 全部 / 用户自助 / 管理员 |
| 搜索框 | 订单号 / 支付流水号前缀 |

## 标记已付

用途：回调失败、银行转账手动对账、测试。

1. 找到目标订单 → 行内「标记已付」
2. 选 `pay_method`（默认 `offline`）
3. 填 `pay_trade_no`（可选，外部流水号）
4. 提交 → 订单变已支付 + 自动激活套餐 / 入账额度

> 管理员手动激活**始终走叠加模式**，不会覆盖已有订阅。

## 标记退款

用途：用户申请退款、纠纷处理。

1. 仅 `status=1`（已支付）的订单可「退款」
2. 行内「退款」→ 二次确认
3. 提交 → 订单变已退款

> **退款不会自动回退已发放的额度 / 撤销订阅**。需要手动：
> - 用户的 [订阅](../subscription/subscription-management) 撤销
> - 用户的 [余额](../schema/user) 调减

## 删除订单（Root only）

用途：测试订单清理、误操作修复。

1. 仅 `status !== 1`（非已支付）的订单可删除
2. Root 账号行内「删除」→ 二次确认
3. 物理删除该订单行

> 物理删除是**不可恢复**的。优先用「退款」或「撤销订阅」处理。

## 常见问题

- **用户反馈付款成功但订单一直「待支付」**：通常是异步回调失败。在订单详情看 `pay_time` / `pay_trade_no`；手动标记已付
- **退款后用户余额还在**：是的，系统不自动回退，需要手动 [调整用户余额](../user/user-management)
- **怎么找到对账用的银行流水号**：在订单详情页看 `pay_trade_no` 字段

## 相关 API

- `GET /api/order/` — 列表（Admin）
- `GET /api/order/search?keyword=` — 关键字搜索（Admin）
- `GET /api/order/:id` — 详情（Admin）
- `PUT /api/order/:id` — 标记已付 / 退款（Admin）
- `DELETE /api/order/:id` — 删除（Root）
