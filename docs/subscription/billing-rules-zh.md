# 计费规则

> 订阅里的额度是怎么扣的、什么时候算用完。

## 三种窗口

每个套餐对每个模型可以设三种"窗口"配额：

| 窗口 | 多长 | 含义 |
|---|---|---|
| `period` | 默认 5 小时 | 短时滚动窗口 |
| `week` | 7 天 | 周配额 |
| `month` | 30 天 | 月配额 |

**任何一个窗口用完都会触发套餐耗尽**。比如你的月配额用完了，即使周配额还有，也会走按量计费。

## 加权使用率

系统计算每个窗口的"使用率"：

```
使用率 = Σ (本窗口已用量 / 配额) × 100
```

任意一个窗口使用率 ≥ 100% 即视为该套餐用尽。

## 计数规则

每个套餐对每个模型可以按两种维度计数：

- **按调用次数**：今天 / 本周 / 本月能调几次
- **按 token 总量**：今天 / 本周 / 本月能用多少 token

具体用哪个看套餐设置（[套餐管理 → 套餐设置](../subscription/plan-management)）。

## 调用扣费顺序

每次请求：

1. **检查订阅**：你的活跃订阅是否覆盖此模型
   - 是 → 在订阅窗口里扣；**不扣账户余额**
   - 否 → 走第 2 步
2. **按量计费**：从 [用户余额](../schema/user) 扣
   - 余额够 → 调用成功
   - 余额不够 → 429 拒绝
3. **缓存**：系统把订阅状态缓存 5 分钟，更新后会失效

## 套餐过期

- 到期后该订阅自动失效
- 失效后调用仍可成功，但走按量计费
- 想恢复折扣：**重新订阅**

## 常见问题

- **看到「剩余额度」跳变**：订阅配额缓存 5 分钟，重启服务或手动触发 invalidate 后会立即刷新
- **刚充值的额度没扣**：检查是否该调用命中了订阅；订阅优先于余额
- **用完了月配额，周配额没动**：是的，三个窗口独立，任意一个耗尽都触发按量计费
