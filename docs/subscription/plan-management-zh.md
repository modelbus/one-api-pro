# 套餐管理（管理员）

> 后台 → 套餐管理。管理员可配。

## 套餐（Plan）是什么

套餐是「可订阅商品」的模板。用户在前台订阅页看到的就是它。

一个套餐由以下信息定义：

| 字段 | 含义 |
|---|---|
| 名称 | 用户看到的名字 |
| 价格 | ¥ |
| 额度 | 调用次数 / token 总量（由 [模型定价](../schema/model-price) 决定单价） |
| 有效期 | 多少天 |
| 折扣倍率 | 订阅期间调用的折扣（如 0.8） |
| 描述 | 富文本，前台展示 |
| 状态 | 上架 / 下架 |
| 推荐 | 开关：前台显示「推荐」徽章 |

## 创建套餐

后台 → 套餐管理 → 新增：

1. 填名称、价格、有效期
2. 填总额度（如 500 万 token / 月）
3. 选每模型的窗口配额（可选；不填则套餐对该模型不限制）
4. 填折扣倍率（默认 1.0，即无折扣）
5. 写描述（富文本）
6. 保存

## 上架 / 下架

- **上架**：用户能在订阅页看到这个套餐
- **下架**：用户不能新订阅，但已有订阅不受影响

通常操作：开发 → 测试 → 上架。出了问题 → 立即下架。

## 删除

不建议直接删（会破坏已订阅用户的关联）。建议流程：

1. 先下架（用户不再新订）
2. 等所有老订阅到期（自然失效）
3. 再删除

## 编辑的影响

| 改了 | 影响 |
|---|---|
| 价格 | 老订阅沿用旧价 |
| 有效期 | 老订阅沿用旧有效期 |
| 折扣倍率 | 老订阅沿用旧倍率 |
| 状态（下架）| 老订阅继续生效 |

**套餐不会回溯更新已订阅用户。**

## 常见问题

- **新增后用户看不到**：检查是否上架了；检查 [套餐业务配置](./plan-settings) 没禁用
- **用户订阅后套餐改价格，老用户继续按原价算吗？** 是
- **删除套餐提示「仍有活跃订阅」**：先让订阅到期，再删
