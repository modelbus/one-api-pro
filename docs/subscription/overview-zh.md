# 订阅概览

> 你账户里的额度怎么扣、订阅能省多少、和余额是啥关系。

## 三种计费方式

One API Pro 同时支持三种计费方式，它们用同一个账号扣费但作用不同：

| 方式 | 是什么 | 扣的额度 |
|---|---|---|
| **订阅（Token Plan）** | 每月 / 每周 / 按天给你一个固定额度池 | 不扣账户余额；订阅内部扣 |
| **按量计费** | 调用一次扣一次的钱 | 扣账户余额（`users.quota`） |
| **充值额度** | 充钱进来，加到账户余额 | 提供「余额」给按量计费扣 |

一个用户可以**同时拥有**以上三种。

## 扣费顺序

每次调用时，系统按以下顺序扣费：

1. **先看订阅**：你的某个活跃订阅是否覆盖这个模型？
   - 是 → 用订阅内的额度（**不扣账户余额**）
   - 否 → 走「按量计费」路径
2. **按量计费**：从你的 [用户额度](../schema/user) 余额里扣
   - 余额够 → 调用成功
   - 余额不够 → 直接 429 拒绝

简而言之：

> 订阅 = 套餐内的额度池（不打账户余额）
> 余额 = 兜底钱，用完就没法调了

## 订阅 vs 充值

| 维度 | 订阅 | 充值 |
|---|---|---|
| 写在 | `subscriptions` 表 | `users.quota` 字段 |
| 有有效期？ | 有，到期后失效 | 没有，长期有效 |
| 有折扣？ | 有（套餐折扣倍率） | 没有 |
| 用法 | 优先扣 | 订阅耗尽后才扣 |
| 过期后？ | 自动失效，走按量计费 | 继续有效 |

## 升级套餐

你已有订阅时再买更贵的套餐：

- **默认（差价模式）**：按「差价」付款，剩余额度按比例折算到新订阅
- **叠加模式**：付全款买新订阅，旧订阅继续生效到原到期日

管理员可在 [套餐业务配置](./plan-settings) 切换。

## 订阅过期

- 到期后订阅**自动失效**
- 失效后调用不会报错，但会走按量计费（按账户余额扣）
- 想要重新获得套餐折扣，**重新订阅**即可
