::: v-pre

### 🔒 Security

- **Removed the Proxy channel type (43) and its adaptor**: it forwarded the HTTP method, path and body verbatim to the channel's `BASE_URL`, effectively acting as an unrestricted egress proxy that could reach `127.0.0.1`, private networks and the `169.254.169.254` cloud metadata endpoint, or smuggle protocols into non-HTTP services such as Redis.
- **Removed the `/v1/oneapi/proxy/:channelid/*target` route**: it let an admin pin an arbitrary channel from the URL and pass any path through, which was the direct entry point for the risk above.
- **Blocked at the channel layer**: creating or updating a channel with `type=43` is rejected, and the frontend type selector no longer offers it, so no usable Proxy channel can be created again.

### 🐛 Bug Fixes

- **Fixed quota being pre-consumed for a channel with no adaptor**: `RelayTextHelper` used to resolve the adaptor *after* pre-consuming quota, so `adaptor == nil` returned a 400 without refunding the pre-consumed amount — users were charged for a failed request. The adaptor is now resolved before pre-consumption, so the failure path costs nothing.

### 🔧 Refactor

- Deleted the `relay/adaptor/provider/proxy` package, `relay/handler/proxy.go`, `relaymode.Proxy` and the related branches. `channeltype.Proxy` stays as a placeholder constant so type numbers from 44 onward keep their meaning.
- `TokenAuth` no longer reads the `:channelid` path parameter; admin token-suffix pinning (`sk-xxx-42`) still works.

### 📚 Documentation

- Dropped the Proxy Forwarding section from the API docs and the matching 「普通用户不支持指定渠道」 entry from the error-code reference.

### ⚠️ Upgrade Notes

- **Breaking change**: `/v1/oneapi/proxy/{channelId}/{path}` now always returns 404. Integrations that relied on it to pass non-OpenAI paths through (e.g. `/v1/rerank`, xinference, FastGPT's bge-reranker) stop working, and the gateway has no equivalent route today.
- **Run the migration script** to disable legacy type-43 channels so they can never be routed again:
  `mysql -u ... oneapi < bin/migration_remove_proxy_channel.sql`
- Legacy type-43 channels render as a grey `Type 43` in the admin console and fail to save with 「Proxy 渠道类型已移除」; disable or delete them.
- Standard endpoints such as `/v1/chat/completions`, all other channel types, billing and logging are unaffected.
