### ✨ New Features

- **Server-side pagination for user management**: `GET /api/user/` now accepts `page` (1-based) and `pageSize` (also `page_size`, capped at 100), and the response keeps the `data` array while adding `total` / `page` / `page_size`. The frontend pager is driven by the real total, renders "N total · Page X of Y", and lets users change the page size.
- **Human-readable validation messages**: new `common.ValidationMessage` maps each validator field + rule to zh/en copy (e.g. "password length must be at least 8 characters"), joins multiple field errors with "; ", and falls back to a generic label for unknown fields — raw strings like `Key: 'User.Password' ... failed on the 'min' tag` are never returned.
- **Testable tab titles**: new frontend pure-function module `src/utils/title.js` with Node unit tests, so title composition (page title + site name, i18n miss fallback) can be verified in isolation.

### 🐛 Bug Fixes

- **Tab title overwritten by the backend**: `/api/status` used to assign `document.title = system_name` (whose default could be `one-api`) on every load, so a refresh replaced the page title with the configured site name. Titles are now derived only from the route `meta.title` plus the fixed site name `ONE-API-PRO`; every page declares `meta.title` and the title refreshes on locale change.
- **Token copy silently failed over HTTP**: `navigator.clipboard` is unavailable in non-secure contexts (plain http) or when permission is denied, and the old implementation only chained `.then`, so nothing happened on failure. Copying is now async with `try/catch`, degrades to a hidden textarea + `execCommand('copy')`, and reports "Copy failed. Please select and copy manually." when even that fails.
- **Misaligned user-list paging**: the old "have we reached the last page" heuristic rendered empty or extra pages when the total changed or pages were clicked quickly, and referenced an undefined `pageTotal`. The page count now comes from the backend `total`, with a `fetchSeq` race guard and out-of-range page fallback.
- **User `total` disagreed with the list filter**: added `model.CountAllUsers()`, which applies exactly the same filter as `GetAllUsers()` (soft-deleted users excluded), so the total stays accurate even when the page is empty.

### 🔧 Refactor

- **Streamlined personal settings page**: removed the "Profile" and "Access Token" sections together with their form state and save logic; both capabilities now live in the top-right user-menu modal, leaving promotion link, third-party bindings and the danger zone on the page.
- **Token modal interaction**: the access-token input now embeds a copy icon in its suffix (with tooltip and `aria-label`), plus the hint "Token (shown only once, please copy and save it)" above it.

### ⚠️ Upgrade Notes

- `data` in `GET /api/user/` remains an array; the new fields are additive. Callers that only send the legacy `p` (0-based page index) parameter keep their current behavior.
- The personal settings page no longer exposes profile editing or access-token generation; use the top-right user menu instead.
- No database schema changes and no migration script required.
