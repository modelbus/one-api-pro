### 🔒 安全

- **移除 Proxy 渠道类型（43）及其 adaptor**：该类型会把请求方法、路径与请求体原样转发到渠道配置的 `BASE_URL`，等价于一个不受限制的出站代理，可借此访问 `127.0.0.1`、内网段与 `169.254.169.254` 云元数据，也可对 Redis 等非 HTTP 服务做协议走私。
- **移除 `/v1/oneapi/proxy/:channelid/*target` 路由**：该路由允许管理员按 URL 固定任意渠道并透传任意路径，是上述风险的直接入口。
- **渠道层面封堵**：新建/编辑渠道时拒绝 `type=43`，前端类型下拉同步移除该选项，避免再次产生可用的 Proxy 渠道。

### 🐛 问题修复

- **修复「无 adaptor 渠道仍被预扣额度」**：`RelayTextHelper` 原先在预扣额度之后才解析 adaptor，`adaptor == nil` 时直接返回 400 而未退还预扣，用户会被扣费却拿不到回答。现在 adaptor 解析提前到预扣之前，失败即返回，不产生任何扣费。

### 🔧 重构

- 删除 `relay/adaptor/provider/proxy` 包、`relay/handler/proxy.go`、`relaymode.Proxy` 与相关分支判断；`channeltype.Proxy` 保留为占位常量，确保 44 及之后的类型编号不偏移。
- `TokenAuth` 移除读取 `:channelid` 路径参数的分支；token 后缀固定渠道（`sk-xxx-42`）能力保持不变。

### 📚 文档

- 删除 API 文档中的 Proxy Forwarding 章节，并从错误码文档移除对应的「普通用户不支持指定渠道」条目。

### ⚠️ 升级注意事项

- **破坏性变更**：`/v1/oneapi/proxy/{channelId}/{path}` 现在一律返回 404。依赖该接口透传非 OpenAI 路径（如 `/v1/rerank`、xinference、FastGPT 的 bge-reranker）的集成将不可用，网关目前没有等效替代路径。
- **必须执行迁移脚本**，把存量 type=43 渠道置为禁用，避免其仍被路由选中：
  `mysql -u ... oneapi < bin/migration_remove_proxy_channel.sql`
- 存量 type=43 渠道在后台列表中显示为灰色的 `Type 43`，编辑保存会提示「Proxy 渠道类型已移除」，请直接禁用或删除。
- 标准 `/v1/chat/completions` 等接口、其它渠道类型、计费与日志逻辑均无变化。
