### ✨ New Features

- **Unified CNY unit across amount-bearing APIs**: `quota` / `used_quota` / `remain_quota` / `bonus_quota` on the user, token, channel, redemption, log, order, top-up setting, option and dashboard endpoints are now returned in **yuan**, and the matching write endpoints accept yuan as well. Storage stays micro-quota (1 CNY = 1,000,000) with all conversion in the controller layer.
- **New one-shot migration script `cmd/migrate_topup_presets`**: rewrites legacy `bonus_quota` values in top-up presets to micro-quota (dry-run by default, `--apply` to persist).

### 🐛 Bug Fixes

- **Fixed the unsavable top-up settings page**: quick amounts introduced in v0.0.10 used a yuan scale, but v0.0.24 switched to micro-quota without migrating existing rows, so `{amount: 10, bonus_quota: 10}` was read as "pay ¥10, credit ¥0.00001" and blocked by validation.
- **Fixed the validation message showing the literal key `bonusTooLow`**: short keys were not bound to the `settingPage.topup` namespace.
- **Fixed the `PreConsumedQuota` unit mismatch**: it now means "extra reserved quota (micro-quota)" instead of "extra pre-consumed token count", which used to be inflated by the `ratio` factor.
- **Unified billing rounding**: `CalculateTokenQuota` and friends now use `math.Round` instead of `int64()` truncation, matching `model.YuanToQuota` and the frontend; audio transcription also gained a minimum-charge floor.
- **Fixed a runtime error in the token edit dialog**: `Token.vue` referenced an undefined `quotaPerUnit`.

### 🔧 Refactor

- **Added `controller/quota_dto.go` as the single conversion choke point**: it embeds the model struct and shadows the amount fields, so only converted fields need to be declared.
- **Conversion stays out of the model layer**: cross-node push, the Redis cache and order snapshots all depend on the model JSON representation; changing units there would corrupt data.
- **Removed all frontend conversion**: `utils/quota.js` keeps only formatting helpers, and 11 components dropped their `quotaPerUnit` dependency.

### 📚 Documentation

- Synced the amount-unit notes in the API and schema docs (from "quota" to "yuan").

### ⚠️ Upgrade Notes

- **Upgrade the frontend and backend together**: an old frontend reads yuan as micro-quota (off by 1e6×) and an old backend stores yuan as micro-quota.
- **Run the migration script**, otherwise the top-up settings page keeps failing on legacy data: `go run ./cmd/migrate_topup_presets` to dry-run, then re-run with `--apply`.
- **Re-check `PreConsumedQuota`**: it now means "extra reserved quota in yuan"; the default stays 500 (¥0.0005).
- `channel.balance` and `ChannelDisableThreshold` are on the USD scale and are not converted.
