# v0.0.25 — API 边界统一为「元」+ 修复充值到账额度口径（附迁移脚本）

> 所有涉及金额的 API 统一以「元」返回与接收，前端不再做任何 1e6 换算；同时修复充值快捷金额因历史数据口径不一致而报「到账金额不能低于支付金额」、以及 `PreConsumedQuota` 被当成 token 数使用的问题。

> Every amount-bearing API now returns and accepts CNY yuan, and the frontend no longer converts anything. Also fixes the top-up preset "credit amount cannot be lower than the pay amount" error caused by legacy data, and `PreConsumedQuota` being treated as a token count.

## 中文

### ✨ 新增功能

- **金额 API 统一「元」口径**：`/api/user`、`/api/token`、`/api/channel`、`/api/redemption`、`/api/log`、`/api/order`、`/api/setting/topup`、`/api/topup/order`、`/api/option`、`/api/user/self/dashboard`、`/api/admin/dashboard/*` 等全部端点的金额字段（`quota` / `used_quota` / `remain_quota` / `bonus_quota`）改为返回**元**；对应的写接口（`PUT /api/user`、`PUT /api/token`、`POST/PUT /api/redemption`、`PUT /api/setting/topup`、`POST /api/topup`、`PUT /api/option`）同样接收**元**。数据库内部仍以微元（1 元 = 1,000,000）存储，换算全部在 controller 层完成。
- **新增一次性迁移脚本**：`cmd/migrate_topup_presets` 用于把 `topup.presets` 中旧口径的 `bonus_quota` 修正为微元（默认干跑，`--apply` 才写回）。

### 🐛 问题修复

- **修复充值设置无法保存（`到账金额不能低于支付金额`）**：v0.0.10 引入的快捷金额使用「元」口径，v0.0.24 将额度基准改为微元后**未迁移存量数据**，导致 `{amount: 10, bonus_quota: 10}` 被按微元解读为「支付 10 元、到账 ¥0.00001」，前端校验直接拦截保存。现提供迁移脚本，并把该值按 1:1 等值修正。
- **修复校验提示显示字面量 `bonusTooLow`**：`validateTopupPresets` 内部使用短 key，而 i18n 把它们定义在 `settingPage.topup` 命名空间下，调用方传入未绑定命名空间的 `t`，vue-i18n 找不到 key 便原样返回 key 字符串。现改为绑定命名空间后再传入。
- **修复 `PreConsumedQuota` 量纲错配**：该配置项在管理端按「元」输入并按 `×1e6` 落库，后端却把它当作 **token 数**加到 `promptTokens` 上预估费用，等于把管理员填写的金额放大了 `ratio` 倍。现修正为「额外预留额度（微元）+ 预估 token 费用」。
- **修复令牌编辑弹窗运行时报错**：`Token.vue` 使用了未定义的 `quotaPerUnit`，打开编辑弹窗即抛 `ReferenceError`。现已随本次改造一并移除。
- **修复计费取整口径不一致**：`CalculateTokenQuota`、`CalculatePerRequestQuota` 及音频转发路径使用 `int64()` 直接截断，而管理端 `model.YuanToQuota` 与前端使用四舍五入，同一笔消费两端可能相差 1 微元。现全部统一为 `math.Round`。
- **修复音频转写缺少最小计费兜底**：`/v1/audio/transcriptions` 的 token 计费路径未复用 `CalculateTokenQuota` 的「结果 ≤ 0 且有 token 时按 1 微元计费」兜底，极短或空文本会按 0 扣费。现已对齐。

### 🔧 重构

- **新增 `controller/quota_dto.go` 作为 API 边界的唯一换算收口**：微元 → 元的输出 DTO 与元 → 微元的输入 DTO 均在此定义。实现上采用「内嵌 model 结构体 + 同名字段遮蔽」，`encoding/json` 选取层级最浅的字段，因此只需声明要换算的字段，其余字段自动透传，改动面最小。
- **明确不在 model 层换算**：`cluster/watcher.go` 的 INSERT 事件用 `json.Marshal(model)` 序列化整行后跨节点推送，`model/cache.go` 把 `model.Token` 的 JSON 存入 Redis，`model/order_payment.go` 保存订单快照——若在 model 层改变 JSON 表示，会分别造成跨节点数据损坏、存量缓存被错误解读、快照单位漂移。因此换算严格限定在 controller 层。
- **前端不再做任何换算**：`utils/quota.js` 收窄为纯格式化工具（仅保留 `formatYuan` / `formatQuota` / `yuanInputPrecision`），删除 `quotaToYuan` / `yuanToQuota` / `quotaToYuanExact` / `resolveQuotaPerUnit` / `DEFAULT_QUOTA_PER_UNIT`；涉及用户、令牌、兑换码、日志、仪表盘、运营设置、充值设置与充值弹窗的 11 个组件同步移除 `quotaPerUnit` 依赖。
- **`orders.plan_info` 快照同步换算**：该字段是嵌套 JSON 字符串，无法用字段遮蔽处理，故在输出时单独把 `bonus_quota` 由微元改写为元，其余字段原样保留。

### 📚 文档

- 同步 API 与数据模型文档中的金额单位说明（由「额度」改为「元」）。

### ⚠️ 升级注意事项

- **前后端必须同时升级**：本次是 API 契约的破坏性变更。旧版前端会把元当微元解读（金额相差 1e6 倍），旧版后端会把新版前端提交的元当微元落库。切勿只升级一端。
- **执行迁移脚本**：升级后请运行 `go run ./cmd/migrate_topup_presets` 查看差异，确认无误后加 `--apply` 写回；否则充值设置页会继续因历史数据报错。
- **复核 `PreConsumedQuota`**：其语义已由「额外预扣的 token 数」改为「额外预留的额度（元）」。默认值 500（即 ¥0.0005）保持不变，若你此前在运营设置中调整过该值，请按新的「元」口径重新确认。
- **`channel.balance` 与 `ChannelDisableThreshold` 未变更**：它们是上游账户余额及其阈值（美元口径），本次不做换算，因为系统内没有 CNY/USD 汇率配置。

## English

### ✨ New Features

- **Unified CNY unit across every amount-bearing API**: `quota` / `used_quota` / `remain_quota` / `bonus_quota` on `/api/user`, `/api/token`, `/api/channel`, `/api/redemption`, `/api/log`, `/api/order`, `/api/setting/topup`, `/api/topup/order`, `/api/option`, `/api/user/self/dashboard` and `/api/admin/dashboard/*` are now returned in **yuan**, and the matching write endpoints (`PUT /api/user`, `PUT /api/token`, `POST/PUT /api/redemption`, `PUT /api/setting/topup`, `POST /api/topup`, `PUT /api/option`) accept yuan as well. Storage stays in micro-quota (1 CNY = 1,000,000) and all conversion happens in the controller layer.
- **New one-shot migration script**: `cmd/migrate_topup_presets` rewrites legacy `bonus_quota` values inside `topup.presets` to micro-quota (dry-run by default, `--apply` to persist).

### 🐛 Bug Fixes

- **Fixed the top-up settings page being unsavable (`credit amount cannot be lower than the pay amount`)**: quick amounts introduced in v0.0.10 used a yuan scale, but v0.0.24 switched the quota base to micro-quota without migrating existing rows. A stored `{amount: 10, bonus_quota: 10}` was therefore read as "pay ¥10, credit ¥0.00001" and blocked by frontend validation. A migration script now fixes those rows to a 1:1 value.
- **Fixed the validation message rendering the literal key `bonusTooLow`**: `validateTopupPresets` uses short keys while i18n defines them under the `settingPage.topup` namespace, so an unbound `t` made vue-i18n return the raw key string. The namespace is now bound before being passed in.
- **Fixed the `PreConsumedQuota` unit mismatch**: the admin UI treated it as CNY and stored `×1e6`, while the backend added it to `promptTokens` as a **token count**, inflating the configured amount by the `ratio` factor. It is now an extra reserved quota (micro-quota) added to the estimated token cost.
- **Fixed a runtime error in the token edit dialog**: `Token.vue` referenced an undefined `quotaPerUnit`, throwing a `ReferenceError` as soon as the dialog opened. Removed as part of this change.
- **Fixed inconsistent rounding**: `CalculateTokenQuota`, `CalculatePerRequestQuota` and the audio paths truncated with `int64()` while `model.YuanToQuota` and the frontend rounded, so the same charge could differ by 1 micro-quota between ends. All paths now use `math.Round`.
- **Fixed the missing minimum-charge floor in audio transcription**: the token-billed path of `/v1/audio/transcriptions` did not reuse `CalculateTokenQuota`'s "≤ 0 with tokens → charge 1 micro-quota" floor, so very short or empty transcripts were billed 0. Now aligned.

### 🔧 Refactor

- **Added `controller/quota_dto.go` as the single conversion choke point at the API boundary**, holding both the micro-quota → yuan output DTOs and the yuan → micro-quota input DTOs. The implementation embeds the model struct and shadows the amount fields with the same JSON name; `encoding/json` selects the shallowest field, so only the converted fields need to be declared and everything else passes through.
- **Deliberately not converting in the model layer**: `cluster/watcher.go` serializes a whole row via `json.Marshal(model)` for INSERT events pushed across nodes, `model/cache.go` stores `model.Token`'s JSON in Redis, and `model/order_payment.go` keeps order snapshots. Changing the model JSON representation would respectively corrupt cross-node data, misread existing cache entries, and drift the snapshot unit. Conversion is therefore strictly confined to the controller layer.
- **The frontend no longer converts anything**: `utils/quota.js` is now a pure formatting helper (`formatYuan` / `formatQuota` / `yuanInputPrecision`), with `quotaToYuan`, `yuanToQuota`, `quotaToYuanExact`, `resolveQuotaPerUnit` and `DEFAULT_QUOTA_PER_UNIT` removed; 11 components across users, tokens, redemptions, logs, dashboards, operation settings, top-up settings and the top-up modal dropped their `quotaPerUnit` dependency.
- **`orders.plan_info` snapshots are converted too**: the field is a nested JSON string that cannot be handled by field shadowing, so `bonus_quota` is rewritten from micro-quota to yuan on output while every other field is preserved.

### 📚 Documentation

- Updated the amount-unit wording in the API and schema docs (from "quota" to "yuan").

### ⚠️ Upgrade Notes

- **The frontend and backend must be upgraded together**: this is a breaking API contract change. An old frontend reads yuan as micro-quota (off by 1e6×) and an old backend stores yuan sent by the new frontend as micro-quota. Never upgrade only one side.
- **Run the migration script**: after upgrading, run `go run ./cmd/migrate_topup_presets` to review the diff, then re-run with `--apply`. Otherwise the top-up settings page keeps failing on legacy data.
- **Re-check `PreConsumedQuota`**: its meaning changed from "extra pre-consumed token count" to "extra reserved quota in yuan". The default stays 500 (¥0.0005); if you previously tuned it under Operation Settings, please re-confirm it under the new yuan scale.
- **`channel.balance` and `ChannelDisableThreshold` are unchanged**: they are the upstream account balance and its threshold (USD scale) and are not converted, since the system has no CNY/USD exchange rate configuration.
