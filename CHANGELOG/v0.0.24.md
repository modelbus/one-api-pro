# v0.0.24 — 额度基准常量化（1 元 = 1,000,000 额度）+ 移除充值兑换比例 + 全链路统一为元

> 将 `QuotaPerUnit` 固定为系统常量 `1_000_000`（语义同微信支付的「分」，1 quota = 1e-6 元），彻底移除 `topup.exchange_rate`：自定义金额恒 1:1，营销赠送（如「充 10 得 15」）通过快捷金额的「支付金额 / 到账金额」双列实现；充值、消费、套餐扣费、日志、统计与管理端输入全部对齐到同一「元」口径，计费日志定价精度由 4 位提升到 6 位。

> `QuotaPerUnit` is now a fixed system constant `1_000_000` (a "cent"-like unit: 1 quota = 1e-6 CNY). `topup.exchange_rate` is removed entirely: custom amounts are always 1:1, while promotions (e.g. "pay 10 get 15") are expressed by the pay/credit columns of quick amounts. Top-up, consumption, plan deduction, logs, stats and every admin input now share the same CNY unit, and billing-log price precision is raised from 4 to 6 decimals.

## 中文

### ✨ 新增功能

- **「支付金额 / 到账金额」双列快捷金额**：充值设置页的快捷金额改为按元输入「支付金额」与「到账金额」，管理员可直接配置「充 10 得 15」这类营销赠送；到账金额不得低于支付金额，保证不出现「充值缩水」。
- **管理端额度输入统一为元**：用户编辑额度、令牌额度限制、兑换码额度、运营设置中的新用户初始额度 / 预扣额度 / 邀请奖励额度 / 额度提醒阈值，全部改为以元（¥）输入；提交时自动换算为内部 quota，接口协议保持不变。

### 🐛 问题修复

- **按次计费改为精确预扣，杜绝余额透支**：`per_request` 定价的文本类模型此前沿用 token 估算口径预扣（仅数百额度），结算时才按按次价格扣款，单次调用即可把 `users.quota` 扣成负数；现改为按按次价格精确预扣，预扣额与结算额一致（差值恒为 0），余额不足时在预扣阶段直接返回 403。同时豁免「usage 为 0 不计费」守卫，避免按次费用被误退回。

### 🔧 重构

- **`QuotaPerUnit` 常量化**：由可写配置改为系统常量 `1_000_000`，不再写入 `options` 表、不出现在 `OptionMap`，后台 `PUT /api/option` 修改 `QuotaPerUnit` 会被明确拒绝；`/api/status` 仍只读下发 `quota_per_unit` 供前端折算。
- **移除 `topup.exchange_rate`**：删除系统设置 key、读取/保存逻辑、存量自愈与兜底换算，以及设置页/接口字段；自定义金额恒 1:1，赠送能力改由快捷金额承担。
- **订单快照字段调整**：`orders.plan_info` 中的 `exchange_rate` 替换为 `credit_amount`（到账金额，元）；历史订单中多余的 `exchange_rate` 字段会被 JSON 解码器自动忽略，到账额度仍以 `bonus_quota` 为准，兼容安全。
- **换算取整防截断**：新增 `model.YuanToQuota` / 前端 `yuanToQuota`，使用四舍五入而非直接截断（如 0.07 元 × 1e6 浮点结果 69999.99… → 70000）。

### 🎨 展示与统计

- **计费日志定价精度 4 → 6 位小数**：`relay/billing/billing.go`、`relay/handler/helper.go`、`relay/handler/image.go` 的定价文案统一为 `%.6f`，与 6 位小数定价及 1e-6 元额度精度对齐。
- **充值弹窗文案**：快捷金额副标题由「送 {n}」改为「到账 {n}」，自定义金额提示按元实时换算展示。
- **标签补充单位**：用户/令牌/兑换码/运营设置等页面的额度字段标签统一补充「(元) / (CNY)」。

### 📚 文档

- 同步「1 元 = 1,000,000 额度」基准、「支付/到账双列」快捷金额与移除 `exchange_rate` 的说明。

### ⚠️ 升级注意事项

- **开发阶段说明**：本次不提供数据迁移脚本；存量额度数据按新基准（1 元 = 1,000,000 额度）重新计算，旧库请自行评估余额与日志口径。
- `topup.exchange_rate` 的数据库行保留但不再读写（遵循「旧字段不主动删除」约定）。
- 若此前依赖兑换比例做赠送，请改用快捷金额的「到账金额」。

## English

### ✨ New Features

- **Pay/Credit quick amounts**: quick amounts in the top-up settings now take a "Pay Amount" and a "Credit Amount" in CNY, so admins can express promos like "pay 10 get 15" directly. Credit can never be lower than pay, preventing under-crediting.
- **Admin inputs unified to CNY**: user quota, token quota limit, redemption quota, and the operation settings (new-user initial quota, pre-consumed quota, inviter/invitee rewards, quota remind threshold) are all entered in CNY; values are converted to internal quota on submit while the API contract stays unchanged.

### 🐛 Bug Fixes

- **Exact pre-consume for per-request billing, no more overdraft**: per-request text models used to pre-consume a token-based estimate (a few hundred quota) while settlement charged the full per-request price, which could drain `users.quota` negative on a single call. They now pre-consume the exact per-request price, so the settlement delta is always 0 and an insufficient balance is rejected with 403 upfront. The "zero usage means no charge" guard is also exempted so per-request fees can no longer be silently refunded.

### 🔧 Refactor

- **`QuotaPerUnit` is now a constant**: previously a writable option, it is now the system constant `1_000_000`, no longer stored in the `options` table or exposed via `OptionMap`; `PUT /api/option` with `QuotaPerUnit` is explicitly rejected. `/api/status` still returns `quota_per_unit` read-only for frontend conversion.
- **`topup.exchange_rate` removed**: the system-setting key, read/save logic, legacy self-heal, fallback conversion and related page/API fields are gone. Custom amounts are always 1:1; bonuses are handled by quick amounts.
- **Order snapshot field change**: `exchange_rate` inside `orders.plan_info` is replaced by `credit_amount` (credited CNY). The extra legacy `exchange_rate` key in old orders is ignored by the JSON decoder, and the credited quota still comes from `bonus_quota`, so compatibility is safe.
- **Rounding instead of truncation**: added `model.YuanToQuota` / frontend `yuanToQuota`, using rounding (e.g. ¥0.07 × 1e6 = 69999.99… → 70000).

### 🎨 Display & Stats

- **Billing log price precision 4 → 6 decimals**: price text in `relay/billing/billing.go`, `relay/handler/helper.go` and `relay/handler/image.go` now uses `%.6f`, aligned with 6-decimal pricing and the 1e-6 CNY quota precision.
- **Top-up modal copy**: quick-amount subtitle changed from "Bonus {n}" to "Credits {n}"; the custom-amount hint converts in real time.
- **Unit labels**: quota fields across user/token/redemption/operation pages now carry "(元) / (CNY)".

### 📚 Documentation

- Synced docs for the `1 CNY = 1,000,000 quota` base, the pay/credit quick-amount columns and the removal of `exchange_rate`.

### ⚠️ Upgrade Notes

- **Development stage**: no migration script is provided; existing quota data is re-interpreted under the new base (1 CNY = 1,000,000 quota). Evaluate balances and logs for legacy databases yourself.
- The legacy `topup.exchange_rate` DB row is kept but no longer read or written (per the "do not actively delete legacy fields" convention).
- If you relied on the exchange rate for bonuses, use the quick amount's "Credit Amount" instead.
