# v0.0.7 — 兑换码（Redeem）

> 上线「兑换码」完整链路：独立 Redeem 页面、侧边栏入口、Dashboard 快捷入口，并把「TopUp」改名为更准确的「Redeem（兑换）」；同时引入双语 CHANGELOG 模板与「CHANGELOG 即 release body」的自动发布流程。

## 中文

### ✨ 新增功能
- 新增 **兑换码（Redeem）页面**：用户在前台输入兑换码即可充值余额，独立路由 `/redeem`，与原有套餐订阅互不耦合。
- 在管理后台侧边栏新增「兑换 / Redeem」入口，配以礼物图标，导航结构更直观。
- Dashboard「快捷操作」区新增兑换入口（替换原 TopUp 卡片），把兑换作为新用户最容易发现的入口之一。
- 接入兑换相关 **i18n 条目**：新增 `zh` / `en` 两套文案，覆盖页面标题、提示文案、空状态、错误信息等。

### 🔧 重构
- 将前端路由 `/topup` 重命名为 `/redeem`，所有跳转与链接同步更新，命名更贴合「兑换码」语义。
- 重构 Dashboard 卡片排序：将「额度信息」下移到兑换表单之下，优先引导新用户使用兑换码。
- 移除已废弃的 `TopUp.vue` 视图，简化页面结构。
- 引入 `CHANGELOG/_template.md`（中英双语模板），后续版本可直接套用，减少格式漂移。
- 新增 `CHANGELOG/README.md`（目录说明），约定每个 tag 必须对应一份 `CHANGELOG/<tag>.md`。

### 🚀 性能优化
- 精简 Dashboard 卡片渲染逻辑，缩短首屏可见时间（兑换卡片优先渲染）。

### 🐛 问题修复
- 修复侧边栏老 TopUp 入口残留在 DOM 中导致的「点开空白」问题。
- 修复 i18n 缺失键导致部分文案回退到 key 名的体验问题。

### 📚 文档
- 新增 `CHANGELOG/_template.md`，统一中英双语格式、章节顺序、emoji 约定。
- 新增 `CHANGELOG/README.md`，说明目录用途、命名规范、发布时如何配套使用。
- 完善 README 中兑换码相关说明（与新页面 / 入口对齐）。

### 🔧 工程 / CI
- 新增 `.github/workflows/release.yml`：tag push 后自动构建 5 平台产物并创建 GitHub Release。
- workflow 直接以 `CHANGELOG/<tag>.md` 作为 Release 说明正文，避免出现 GitHub 自动追加的 `Full Changelog` 链接。
- 当对应版本的 CHANGELOG 文件缺失时，workflow 直接报错并中止发布，强制要求每个 tag 都先有完整的 release notes。
- 在 `.gitignore` 中忽略 `.release-body.md` 等临时产物。

### ⚠️ 升级注意事项
- **路由变更**：原 `/topup` 路由已重命名为 `/redeem`，若有外部链接或书签请同步更新。
- **前端强制重新构建**：本次升级包含页面结构调整、路由重命名与侧边栏变化，建议清空浏览器缓存或使用无痕模式验证。
- **发布流程约束**：从本版本起，打 tag 前必须先在 `CHANGELOG/<tag>.md` 提交本次版本的 release notes，否则 GitHub Actions 会拒绝发布。

## English

### ✨ New Features
- Added a dedicated **Redeem (兑换码) page** accessible at `/redeem`, letting users top up their balance by entering a redeem code, independent of the existing plan-subscription flow.
- Added a new sidebar entry "兑换 / Redeem" with a gift icon for clearer navigation.
- Surfaced Redeem as a Dashboard quick action, replacing the legacy TopUp card so new users discover it first.
- Shipped dedicated **i18n entries** for the Redeem flow in both `zh` and `en`, covering page titles, hints, empty states and error messages.

### 🔧 Refactor
- Renamed the `/topup` route to `/redeem` and updated all internal links and references; the new name matches the underlying "redeem code" semantics.
- Rebalanced the Dashboard quick-actions layout: pushed quota info below the Redeem form to prioritize the redemption path.
- Removed the obsolete `TopUp.vue` view to reduce dead code.
- Added `CHANGELOG/_template.md`, a bilingual (zh/en) template that standardizes sections, order and emoji conventions for future releases.
- Added `CHANGELOG/README.md` documenting the directory layout, naming convention, and how it ties into the release pipeline.

### 🚀 Performance
- Trimmed Dashboard card rendering so the redeem entry becomes interactive sooner after page load.

### 🐛 Bug Fixes
- Fixed a stale TopUp sidebar entry that opened to a blank pane after the rename.
- Fixed missing i18n keys that caused parts of the Redeem UI to fall back to raw key strings.

### 📚 Documentation
- Introduced `CHANGELOG/_template.md` (bilingual release notes template).
- Introduced `CHANGELOG/README.md` (directory guide + release-flow contract).
- Refreshed the README so redeem-related instructions match the new page / sidebar entry.

### 🔧 Tooling / CI
- Added `.github/workflows/release.yml`: pushes of `v*` tags now build all five platform binaries and create a GitHub Release automatically.
- The workflow uses `CHANGELOG/<tag>.md` directly as the release body, avoiding GitHub's auto-generated `Full Changelog` line.
- If `CHANGELOG/<tag>.md` is missing, the workflow now fails fast instead of falling back to auto-generated notes — every tagged release must ship with its own notes.
- Added `.release-body.md` (and similar transient files) to `.gitignore`.

### ⚠️ Upgrade Notes
- **Route change**: `/topup` has been renamed to `/redeem`; update any external links, bookmarks or reverse-proxy rules accordingly.
- **Hard refresh recommended**: the sidebar, dashboard layout and routing have changed; please verify in an incognito window or after clearing the browser cache.
- **Release contract**: starting with this version, every tag pushed to `master` MUST have a matching `CHANGELOG/<tag>.md` committed beforehand, otherwise the release workflow will refuse to publish.
