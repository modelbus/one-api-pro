# v0.0.23 — 充值额度基准统一（1 元 = 1 元）+ 展示折算为元

> 修复「模型定价 / 充值扣除 / 实际到账」三处口径不一致：充值兑换比例改为锚定系统 `QuotaPerUnit`，充 1 元即到账 1 元额度；存量脏数据（历史 `1` / `100000`）读取时自动归一，无需迁移脚本；控制台余额、日志、令牌、兑换码、管理台与充值弹窗统一按 `quota_per_unit` 折算为 ¥ 展示。

> Fixes the three-way inconsistency between model pricing, top-up deduction and actual credit. The top-up exchange rate is now anchored to the system `QuotaPerUnit`, so ¥1 credits ¥1; legacy dirty values (`1` / `100000`) self-heal on read with no migration script; balances, logs, tokens, redemption codes, the admin dashboard and the top-up modal now all render ¥ based on `quota_per_unit`.

## 中文

### 🐛 问题修复

- **充值兑换比例绕过系统基准**：「1 元 = X quota」的默认值原本是 `1`，与 `QuotaPerUnit`（默认 500000）脱钩，导致充 10 元只到账 10 quota（约 0.00002 元）。现改为以 `QuotaPerUnit` 为基准。
- **存量脏数据自愈**：历史 `topup.exchange_rate = 1`（旧默认）与 `100000`（旧文档推荐）在读取时自动归一为 `QuotaPerUnit`；高于基准值视为管理员主动配置的赠送倍率并保留。**无需数据迁移脚本**。
- **保存校验收紧**：`exchange_rate` 由「> 0」改为「>= QuotaPerUnit」，拒绝再次写入「充 1 元到账不足 1 元」的配置。
- **`QuotaPerUnit` 可被设为 0**：该值是计费与充值的换算分母，置 0 会引发除零及「1 元 = 1 quota」退化；后台保存时新增正数校验。
- **日志货币符号不一致**：`LogQuota` 使用全角 `＄`，与计费日志的 `¥` 不一致，统一为 `¥`。

### 🔧 界面

- **额度统一折算为元**：控制台余额卡片、模型用量表格、日志页统计与列表、令牌页剩余/已用额度、兑换码页额度、管理台消费榜单与用量卡片、充值弹窗的「送」与「将获得」，全部按 `/api/status` 下发的 `quota_per_unit` 折算为 `¥` 展示。
- **新增前端工具 `src/utils/quota.js`**：`resolveQuotaPerUnit` / `quotaToYuan` / `formatYuan` / `formatQuota`，配套 Node 单测。小数位随量级自适应，`¥0.0025` 这类小额不再被显示为 `¥0.00`。
- **充值设置页**：兑换比例默认值改为读取 `quota_per_unit`，输入框下限与后端校验一致；「添加」快捷金额按 `amount × 基准比例` 生成到账额度。

### 📚 文档

- 充值配置与充值 API 文档（中英）：修正 `exchange_rate` 校验说明、推荐预设金额（10 元 → 5,000,000 额度）与存量自愈说明。

### ⚠️ 升级注意事项

- 无需数据库迁移：存量 `topup.exchange_rate` 会在读取时自动归一。
- 若此前按旧文档配置了 `exchange_rate = 100000`，升级后该值会被归一为 `QuotaPerUnit`，**自定义金额到账额度会变化**。
- 若管理员确实希望赠送（如 2 倍），请显式设置为 `2 × QuotaPerUnit`。
- 已创建的订单沿用下单时的快照汇率，不受影响。

## English

### 🐛 Bug Fixes

- **Top-up rate bypassed the system base**: the default "1 CNY = X quota" value was `1`, decoupled from `QuotaPerUnit` (default 500000), so paying ¥10 credited only 10 quota (~¥0.00002). The rate is now anchored to `QuotaPerUnit`.
- **Legacy values self-heal**: historical `topup.exchange_rate = 1` (old default) and `100000` (old doc recommendation) normalize to `QuotaPerUnit` on read; values above the base are kept as an explicit bonus multiplier. **No migration script needed**.
- **Tighter validation**: `exchange_rate` changed from "> 0" to ">= QuotaPerUnit", so under-crediting configs can no longer be saved.
- **`QuotaPerUnit` could be set to 0**: it is the divisor for billing and top-up conversion; 0 causes divide-by-zero and 1-quota-per-yuan degradation. Added a positive-number guard on save.
- **Inconsistent currency symbol**: `LogQuota` used a full-width `＄` while billing logs use `¥`; unified to `¥`.

### 🔧 UI

- **Quota rendered as CNY everywhere**: dashboard balance card, model usage table, log stats and rows, token remaining/used quota, redemption quota, admin dashboard rankings and usage cards, and the top-up modal's bonus/"will receive" values now render `¥` based on `quota_per_unit` from `/api/status`.
- **New frontend util `src/utils/quota.js`**: `resolveQuotaPerUnit` / `quotaToYuan` / `formatYuan` / `formatQuota`, with Node unit tests. Decimal places adapt to magnitude so `¥0.0025` is no longer shown as `¥0.00`.
- **Top-up settings**: the rate default now comes from `quota_per_unit`, the input minimum matches backend validation, and "Add preset" derives the credited quota from `amount × base rate`.

### 📚 Documentation

- Top-up configuration and API docs (zh/en): corrected the `exchange_rate` validation, recommended presets (¥10 → 5,000,000 quota) and the legacy self-heal notes.

### ⚠️ Upgrade Notes

- No database migration is required: existing `topup.exchange_rate` values normalize on read.
- If you previously configured `exchange_rate = 100000` per the old docs, it will normalize to `QuotaPerUnit` — **custom-amount credits will change**.
- To intentionally grant a bonus (e.g. 2x), set it explicitly to `2 × QuotaPerUnit`.
- Existing orders keep the rate snapshotted at checkout and are unaffected.
